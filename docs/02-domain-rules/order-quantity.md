# 규칙: 발주량 산출 (R-OQ)

최종 갱신: 2026-09-13 · 출처: stage1.md §4 §5 §6 §7 §9, 데이터 설명.docx, 회의록, D-007

## DoS

| ID | 규칙 |
|---|---|
| R-OQ-01 | `DoS = 월말재고 ÷ 월평균사용량 × 30`. 월평균사용량은 최근 6개월 (R-FC-03). |
| R-OQ-02 | 품목마다 `목표 DoS 일수` 를 관리한다. 품목담당자 설정 → SCM팀장 승인. 설정·변경 이력(담당자, 시각) 보관. |
| R-OQ-03 | 목표 DoS 미설정 품목은 **발주 확정을 차단**한다 (담당자 입력 전까지). |
| R-OQ-04 | 최종 발주량은 발주 후 예상 DoS 가 목표치 아래로 내려가지 않도록 결정한다. |
| R-OQ-05 | 목표 DoS 기본값은 30일이나 기종별로 다르게 둘 수 있다 (예: 월 500대 기종 15일, 월 1대 기종 60~90일). 값을 바꾸면 발주량이 즉시 재계산되어야 한다. |

## Flexibility rule

| ID | 규칙 |
|---|---|
| R-OQ-10 | Supplier 제출 OL 대비 허용 범위: 리드타임 이후 첫 번째 월 **±20%**, 그다음 월~다다음 월 **±30%**, 4~6개월 이후 **제한 없음**. 비율은 설정값. |
| R-OQ-11 | OL 제출 선행 개월 = 기본 **1개월**, 관리자 설정값 (D-003). |
| R-OQ-12 | 시스템은 범위만 보여주지 않고 **허용 범위 안에서 하나의 최종 발주량을 자동 선택**한다. |
| R-OQ-13 | 선택 우선순위: ① 품절 가능성 최소 → ② 목표 DoS 충족 최소 수량 → ③ 월말 재고금액 최소. |

## 추가 수요 반영

| ID | 규칙 |
|---|---|
| R-OQ-20 | 반영 우선순위: ① 수주 확정건 자동 반영 → ② 수급회의 승인건 (SCM 담당자가 결과 입력) → ③ 영업 확률만 높은 건은 **반영 안 함**. |
| R-OQ-21 | 수주 확정 시 증빙파일 불요, **최종 승인된 주문번호 필수**. |
| R-OQ-22 | 파트너 선주문은 `수주 확정` 또는 `수급회의 승인` 전까지 발주 수요에 반영하지 않는다. |
| R-OQ-23 | Bulkdeal(이벤트성 대량거래)은 일반 조정 범위를 벗어나므로 **별도 추가 발주 수요**로 기존 로직 위에 가산한다. |
| R-OQ-24 | Bulkdeal 추가 발주는 SCM팀장 승인 필수. 사유에 **대상 고객, 기종, 수량** 포함. 증빙파일 불요. |
| R-OQ-25 | Bulkdeal 은 별도 리스트로 관리하고, 트렌드/평균 계산에서 **제외**한다 (R-FC-05). |

## MOQ 및 제약

| ID | 규칙 |
|---|---|
| R-OQ-30 | 품목별 최소주문수량(MOQ)을 반드시 반영. 최종 발주량은 MOQ 단위로 **올림** (필요 120, MOQ 50 → 150). |
| R-OQ-31 | MOQ 미설정 품목은 MOQ = 1. |
| R-OQ-32 | 포장단위·최소주문금액은 현재 **미적용**. 향후 추가 가능하도록 설정 구조(컬럼/테이블)만 준비. |
| R-OQ-33 | MOQ·목표 DoS·포장단위 등 품목 설정값은 **파일 업로드와 관리자 화면 입력 둘 다** 지원. 실데이터 전까지 더미값 시드, `is_dummy` 로 표시 (D-007). |

## 확정·승인

| ID | 규칙 |
|---|---|
| R-OQ-40 | 시스템 제안 발주량 → SCM 품목담당자 확정 → SCM팀장 승인. 각 단계 담당자·시각 이력. |
| R-OQ-41 | 산출 결과에는 근거(예측값, 재고, 입고예정, DoS, Flex 범위, MOQ 올림 전 값)를 함께 저장해 설명 가능해야 한다. |

## 산출 순서 (요약)
```
필요량 = 필요월도 예측수요 + 목표DoS 재고 − (전월말 현재고 + 입고예정[창고입고완료])
       + 확정 추가수요(수주확정·수급회의승인) + Bulkdeal
→ Flex 범위 클램프 (R-OQ-10~13)
→ MOQ 올림 (R-OQ-30)
→ 담당자 확정 → 팀장 승인
```
