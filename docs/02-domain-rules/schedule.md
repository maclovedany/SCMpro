# 규칙: 발주 시점 · 일정 · 알림 (R-SCH)

최종 갱신: 2026-09-14 · 출처: stage1.md §3 §8, D-007, D-024 · 구현: migrations/20260913004000_schedule.sql (fn_business_day·fn_order_calendar·fn_submission_*·fn_tick·pg_cron), engine tick/notify, 화면 /schedule, /admin/suppliers

## 발주일

| ID | 규칙 |
|---|---|
| R-SCH-01 | 발주는 수시가 아니라 **매월 정해진 발주일**에만. `발주마감일` 이라는 별도 용어는 쓰지 않는다. |
| R-SCH-02 | 공급처마다 출항일이 다르다. 공급처별 출항일 + 해외법인(공급처)별 출항 준비기간으로 발주 일정 관리. 공급처 추가 시 관리자가 준비기간 입력·변경. |
| R-SCH-03 | 공급처 출항일을 **주차별로 묶어** 발주한다. |
| R-SCH-04 | 발주일·입고예정일이 주말/공휴일이면 **이전 영업일**로 당긴다. 공휴일 캘린더 필요 (Q-009). |
| R-SCH-05 | 선적 리드타임 약 1주. `요청 발주일 + 7일` = 이상적 입고예정 반영 시점이자 확정 기준. |
| R-SCH-06 | 공급처 마스터(5곳, 출항일 주차, 출항 준비기간, 리드타임)는 **파일 업로드와 관리자 화면 입력 둘 다** 지원. 실데이터 전까지 더미값 시드, `is_dummy` 로 표시 (D-007). |

## 입고 차이

| ID | 규칙 |
|---|---|
| R-SCH-10 | 계획 입고일과 실제 입고일을 함께 저장. 차이 = 실제 − 계획 (일수). 조기/지연으로 분류하지 않고 **차이값** 하나로 관리. |
| R-SCH-11 | 입고 차이는 공급처별·품목별·월별로 조회·통계 가능해야 한다. |

## 수요자료 제출

| ID | 규칙 |
|---|---|
| R-SCH-20 | 월간 수요자료 제출 마감 = **전월 말일의 하루 전** (3/31 말일 → 3/30). |
| R-SCH-21 | 마감까지 미제출 부서에 제출 완료 시까지 **10분마다** 알림. |

## 알림 공통

| ID | 규칙 |
|---|---|
| R-SCH-30 | 모든 알림은 시스템 알림 + 이메일. 발송 대상·시각·확인 여부·발송 결과 이력 보관. |
| R-SCH-31 | **알림 on/off (D-046)**: 시스템 설정 `notify_enabled`(전체 — false 면 시스템 알림 insert 자체를 트리거가 차단), `notify_email_enabled`(false 면 이메일 복제·발송 안 함, 대기분은 skipped:disabled 로 마감), `notify_reminders_enabled`(false 면 만료 예고·승인 독촉·미제출 독촉을 tick 이 건너뜀). 배정 만료 처리 등 업무 동작은 설정과 무관하게 계속된다. |
