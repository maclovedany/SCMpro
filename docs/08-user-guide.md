# 사용자 가이드 — 역할별 시나리오

최종 갱신: 2026-09-13 · 대상: 실제 사용자(비개발자) · 화면 규칙은 `02-domain-rules/ui.md`, 업무 규칙은 `02-domain-rules/*`
로그인: http://localhost:3001 (운영 배포 후 주소 교체) · 계정은 관리자에게 문의 · 어느 화면에서든 상단 **AI Agent** 버튼으로 질문 가능

## 대시보드 읽는 법
역할에 맞춰 5묶음이 정렬됩니다(노랑 = 주의, 빨강 = 즉시 조치). 카드를 누르면 그 숫자의 근거 목록으로 이동합니다.
- **재고 건전성** — 월말 예상 재고금액(목표 대비, 이번 달 계획 기준), 카테고리별 평균 DoS(목표 대비), 과잉 재고(DoS 가 목표 2배 이상) 품목·묶인 금액 → KPI 인 월말 재고수량·금액을 미리 보는 곳
- **품절·결품 리스크** — 품절 위험 품목(A 등급 수 강조), 가용재고 0 인데 영업 주문이 기다리는 품목, 계획일이 지난 미입고 PO
- **이번 달 발주 사이클** — 계획 상태와 다음 발주일 D-n, 총 발주 금액(전월 승인·제출 OL 대비), 수요자료 미제출 부서
- **예측 신뢰도** — 기준예측 WAPE vs SCM OL vs Sales OL, 예측이 언제 데이터까지 반영됐는지, AI 조정 제안 대기
- **주문·배정 운영** — 승인 대기(종류·최장 대기 시간), 임시배정 7일 내 만료, 배정 대기 주문·부족 수량
- **데이터 준비 현황**(관리자만) — 더미 품목, 목표 DoS 미설정, 재고 스냅샷 기준일·최근 업로드. 다른 역할은 더미가 남아 있을 때만 한 줄 안내

## 사이드바 구성
메뉴는 업무 흐름 기준 6그룹입니다 — **현황**(대시보드·알림) · **계획**(품목·예측·발주 계획·추가 수요) · **운영**(영업 주문·재고 배정·배정 우선순위·일정·제출) · **결재**(승인함) · **데이터**(업로드·품목 설정·예측 기법) · **관리**(맨 아래: 시스템 설정·공급처·공휴일·EOL/EOS·AI 통계). 역할에 따라 보이는 항목만 나타나고, 승인 대기·미읽음 알림은 숫자 배지로 표시됩니다. 그룹 제목을 누르면 접힙니다.

## 1. SCM 품목담당자 (`item_manager`) — 가장 많이 쓰는 역할

### 1-1. 월초: 데이터 준비 (5단계)
1. **데이터 업로드** → 대상 "재고 스냅샷" 선택 → 템플릿 다운로드 → 창고 재고를 채워 올린다. 컬럼이 자동 매핑되고 "검증"에서 오류 행(없는 품목코드, 날짜 형식)이 걸러진다 → "반영". 결과 카드의 오류 건수를 눌러 무엇이 빠졌는지 확인.
2. 같은 방식으로 **입고예정**(PO·계획일·수량), 필요 시 **품목 설정**(MOQ·단가) 업로드.
3. **대시보드**에서 "재고 스냅샷 기준일"이 오늘로 바뀌었는지, "목표 DoS 미설정"이 0 인지 확인. 0 이 아니면 카드를 눌러 해당 품목을 **품목 설정**에서 채운다(팀장 승인 필요).
4. **추가 수요**: 수주 확정 건(주문번호 필수), 수급회의 승인분, Bulkdeal(고객·기종·수량·사유, 주문번호는 선택 → 팀장 승인 요청)을 등록. 같은 품목·필요월에 승인된 Bulkdeal 이 있는데 수주 확정을 또 등록하면 **이중 계상 경고**가 뜬다 — 같은 거래면 한쪽을 취소.
5. **예측** 화면에서 최근 프로덕션 예측이 있는지(카드 "최근 프로덕션 예측") 확인. 없거나 오래됐으면 "런"에서 프로덕션 예측을 요청(엔진이 처리).

### 1-1b. 과거 연도 출고 실적 넣기 (예측 학습 데이터 늘리기)
예측 엔진은 시스템에 있는 **모든 기간**을 학습합니다. 지금은 2023년 4월부터 있으므로 2021·2022년을 넣으면 학습 구간이 그만큼 늘어납니다.
1. **데이터 업로드** → 대상 **"출고 실적 추가"** 선택.
2. 회사에서 쓰는 출고 파일(부품·소모품·옵션, 월이 열로 늘어선 형식)을 **그대로** 올린다. "넓은 형식 감지" 안내가 뜨면 품목코드 열과 **품목 유형(부품/소모품/옵션)** 만 고른다. 한 줄이 한 달인 긴 형식(품목코드·월·수량·품목유형)도 된다.
3. "검증" → 없는 품목코드·숫자 아닌 칸이 걸러진다 → "반영". 이미 있는 달은 새 값으로 덮어쓴다.
4. 1분 안에 품목 차트·통계에 반영된다(대량 재계산은 백그라운드). 부품의 옛 코드는 최종 발주 코드로 자동 합산된다.
5. **예측 › 런** 에서 "백테스트 요청"과 "프로덕션 예측 요청"을 눌러 새 학습 구간으로 다시 계산한다(엔진 처리 후 반영). 런 상세의 "직전 대비" 로 데이터 추가 효과(오차 변화)를 확인.

### 1-2. 월중: 발주 계획 만들기
1. **발주 계획** → 발주월 입력 → "계획 생성 / 재생성" (약 20초). 카드: 라인 수·총 발주금액·품절 위험·확정 차단·Flex 도달.
2. **품절 위험** 카드를 눌러 필요월도 기초재고가 수요보다 적은 품목부터 본다. 라인 표의 근거 열(현재고·입고예정·예측·추가수요·기초·목표재고·필요량·Flex 범위·MOQ·제안 발주)로 왜 그 수량인지 확인.
3. 재고전개 그리드에서 카테고리를 펼쳐 품목의 월별 예측·입고·기초·기말을 보고, 조정이 필요하면 "확정 발주" 셀(또는 라인 클릭) → 수량 + **사유** 입력. 오버라이드는 이력에 남는다.
4. 설정(목표 DoS·MOQ·리드타임)을 바꿨다면 "재생성" — 초안이 새로 계산된다(오버라이드는 초기화되니 확정 전에 정리).
5. "확정 → 팀장 승인 요청". 차단 품목(목표 DoS 미설정)이 있으면 확정이 막힌다.
6. 승인 후 **보고서**(총액, 전월 승인 대비, 제출 OL 대비, 카테고리·공급처별, 상위 20) → CSV/인쇄 → 사장 보고 · FX-LIVE 입력.

### 1-3. 수시: 재고 배정
- **재고 배정** 화면 상단 카드로 대기 주문·배정 가능·입고 대기·승인 대기를 본다.
- 입고가 오면 "입고 완료" → 재고에 반영되고, **자동 배정 품목**은 대기 주문에 우선순위→요청순으로 자동 배정(담당자·영업에게 알림). **수동 배정 품목**은 알림만 오고 담당자가 큐에서 "수동 배정".
- 큐 순번 1 이 아닌 주문을 먼저 주고 싶으면 "우선 배정(승인)" → 사유 필수 → 수량이 "승인대기 확보수량"으로 잠기고 팀장에게 10분마다 독촉 알림 → 승인 시 확정배정.
- 확정배정을 풀어야 하면 **영업 주문**(전체 보기)에서 "확정배정 해제" + 사유 → 주문은 취소되고 재고는 가용으로 복귀(복구 불가, 재진행은 새 주문).

### 1-4. 품목 설정 변경
**품목 설정** → 품목 코드 조회 → 목표 DoS / MOQ / 단가 / 입고 배정방식 수정 + 사유 → "승인 요청". 승인 전까지 잠김. 하단에 변경 이력.

### 1-5. 예측 품질 관리
- **품목 상세 › 예측 검증**: 이 품목을 2년(이력 시작~2025-03)으로 학습해 FY25(2025-04~2026-03)를 예측한 값과 실제 출고를 월별로 비교. 챔피언 기법의 WAPE·Bias, 기법을 바꿔 가며 비교, 월별 차이 표. "이 품목 예측을 얼마나 믿을 수 있나"의 근거.
- **예측** → 카드로 시스템 기준예측 vs SCM OL vs Sales OL 오차. ABC-XYZ 셀을 눌러 어떤 품목이 A 등급인지 확인.
- **예측 › 런** → 백테스트 결과 상세(레벨별 오차, 기법별 성적). "AI 오차 분석·조정 제안"이 있으면 진단을 읽고 타당하면 "팀장 승인 요청" — 승인되면 다음 런부터 파라미터 적용.
- 기법을 켜고 끄려면 **예측 기법**(관리자 메뉴, 품목담당자도 접근).

## 2. SCM팀장 (`scm_lead`) — 결재와 감독

1. **알림** 또는 **승인함 › 대기** 에서 결재 건 확인. 종류: 품목 설정 변경, 발주 계획, Bulkdeal 추가 발주, 우선 배정, AI 예측 조정.
2. 각 건의 설명(무엇이 어떻게 바뀌는지)과 사유를 읽고 **승인**(의견 선택) 또는 **반려**(사유 필수). 승인은 즉시 반영된다 — 발주 계획 승인 = 제출 OL 기록, 우선 배정 승인 = 확정배정, 설정 승인 = 값 반영.
3. 우선 배정 승인 대기는 처리 전까지 **10분마다** 알림·이메일이 반복된다(승인·반려하면 중단).
4. **발주 계획**에서 승인 전 계획의 품절 위험·오버라이드 현황을, **예측**에서 예측 정확도 추이를 본다.
5. **영업 주문(전체 보기)**·**재고 배정**·**배정 우선순위** 는 조회·조정 가능.

## 3. 영업부 (`sales`)

1. **영업 주문** → 품목 코드 입력 → "가용재고 조회": 현재고 − 임시배정 − 확정배정 − 승인대기 = **가용**. 이 숫자가 실제로 약속할 수 있는 수량.
2. 수량·고객 입력 → 가용이 부족할 때의 처리 선택: **부분 임시배정**(가능한 만큼 지금 잠그고 나머지 대기) 또는 **전체 배정 대기** → "검토 요청 등록". 즉시 임시배정(30일, 연장 불가).
3. 목록에서 내 주문의 상태·임시/확정/부족 수량·만료일 확인. 만료 10·5·3·2·1일 전 알림이 온다. 30일 안에 **수주 확정**을 누르면 확정배정으로 전환(만료 없음). 취소는 사유 필수.
4. 만료로 자동 해제된 주문은 복구되지 않는다 — 새 검토 요청을 등록.
5. 입고로 자동 배정되면 알림이 온다. 대기 중 순서는 **배정 우선순위**(사업강화부)와 요청 순서로 정해진다.
6. **일정·제출**에서 다음 달 수요자료 "제출" 버튼을 마감(전월 말일 하루 전) 전에 누른다 — 안 누르면 10분마다 독촉 알림.

## 4. 마케팅부 / 서비스부 (`marketing`, `service`)

1. **일정·제출** → 다음 달 수요자료 제출(마감 전).
2. **품목**에서 담당 품목(마케팅: 용지·카드리더기, 서비스: 소모품) 검색 → 현재고·DoS·예측·입고예정 확인.
3. **알림**에서 미제출 독촉·공지 확인. 긴급 발주가 필요하면 담당자에게 요청(추가 수요 등록은 SCM).

---

## 5. 사업강화부 (`biz_enable`)

1. **배정 우선순위** → 진행 중(임시배정·부분·대기) 주문 목록. 전략 고객 건의 우선순위 숫자를 낮추고(작을수록 먼저) 사유 입력 → 저장. 변경 전후·변경자·시각은 이력에 남는다.
2. 이후 입고 자동 배정은 이 우선순위 → 요청 순서로 진행된다.
3. **영업 주문**에서 배정 상황을 조회.

## 6. 관리자 (`admin`) — 설정과 운영

1. **시스템 설정**: 회계연도 시작월, OL 제출 선행 기간, Flex 허용 범위(표), DoS 기간, 리드타임, 임시배정 기간, 만료 예고 일수, 반복 알림 간격, 제출 마감·부서, 재고전개 표시 개월, AI 모델. 값은 목록·숫자·체크박스로 고른다. 변경은 다음 계산(계획 재생성·다음 런·다음 알림)부터 적용.
2. **공급처**: 5개 공급처의 출항 준비일·리드타임·출항 요일/주차. **공휴일**, **EOL/EOS**(기종 출시·판매종료·서비스종료).
3. **예측 기법**: 기법 on/off·파라미터, ABC-XYZ 셀별 후보. 기준선(6M 평균)은 끌 수 없다.
4. **AI 질문 통계**: 사용자들이 무엇을 묻는지(주제·일별·사용자별·질문 목록) → 교육·기능 개선에 활용.
5. 계정: `web/scripts/seed-users.mts` 로 생성/비밀번호 초기화(개발자 도움). 역할은 관리자·품목담당자·SCM팀장·영업·마케팅·서비스·사업강화.
6. 운영 점검: **대시보드**의 더미 데이터 비율(실데이터 업로드로 0% 가 목표), 승인 대기, 스냅샷 기준일. 엔진 실행(예측·tick)은 개발자/운영 담당이 `CLAUDE.md` 실행 섹션대로.

- "556K59129 현재고랑 DoS, 챔피언 예측 기법 알려줘" → 품목 조회 도구로 근거 수치와 함께 답변
- "이번 달 발주 계획에서 품절 위험 품목 몇 개야?" / "MDL213 다음 달 예측값은?"
- "내 승인 대기 뭐 있어?" / "다음 발주일 언제야?" / "영업부 수요자료 제출했어?"
- 답변은 로그인한 사용자가 볼 수 있는 데이터만 사용하며, 시스템에 없는 사실은 "확인되지 않는다"고 답한다. 패널 너비는 왼쪽 경계를 드래그해 조절.

## 8. 자주 묻는 질문
- **"계획 생성"이 오래 걸려요** → 약 20초. 오류가 뜨면 "다시 시도". 예측이 없으면 먼저 예측 실행 필요.
- **카드 숫자가 이상해요** → 카드를 눌러 목록을 보면 근거가 나온다. 더미 데이터(회색 "더미" 배지)는 실데이터 업로드 시 사라진다.
- **알림 이메일이 안 와요** → 시스템 알림은 화면에 항상 남는다. 이메일은 10분 주기로 발송(발신 insightdany@naver.com, 스팸함 확인). 10분 넘게 안 오면 개발 Mac 의 launchd 잡(`/tmp/scmpro/tick.log`)을 확인.
- **비밀번호를 잊었어요** → 관리자가 `npm run seed:users` 로 초기화(1q2w3e). 로그인 후 변경 권장.
- **품목 예측을 얼마나 믿을 수 있나요?** → 품목 상세 아래 "예측 검증": 2년 학습 → FY25 예측 vs 실적의 월별 차이와 WAPE 를 보면 된다.
- **부품 코드가 여러 개인데 어떤 걸로 검색?** → 최종 발주 코드(HOC)로 통합 관리된다. 옛 코드로 검색해도 상세의 "XCN 연계 코드"에서 확인 가능.
